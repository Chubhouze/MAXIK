# M.A.X.I.K. — модуль распознавания состояния растений (Computer Vision)

Цель по заявке (раздел 14): **≥ 75% верной классификации** на контролируемом датасете, ≥ 50 пригодных фото,
классы `healthy / dryness / yellowing / weak_damage / unknown`, работа на Raspberry Pi 4.

> В проекте два конвейера. **Томатный (раздел ниже)** — основной: робот снимает растение, система говорит
> *что это за состояние*, *насколько оно плохо* и *что может быть не так*, и ведёт историю по каждому растению.
> Конвейер «универсальный, 4 состояния» (раздел «Архитектура» и далее) — более ранний, обучен только на
> синтетике и остаётся как есть.

## Томатный конвейер: робот → фото → ML → «насколько плохо» и «что не так»

```
робот: фото (+ ID точки, датчики: влажность почвы, температура, влажность воздуха)
   │  по Wi-Fi на сервер (POST /api/tomato)  — или анализ на самом роботе (--local)
   ▼
1. качество кадра: тёмный / пересвеченный / смазанный / растение слишком мелкое  → «переснимите»
2. ворота «это растение?» (обученный бинарный классификатор)                      → NOT_PLANT
3. вид растения (сейчас ЗАГЛУШКА: любое растение считается томатом)
4. болезнь: MobileNetV3-Large, 10 классов (здоров + 9 болезней/вредителей)
5. порог уверенности: слабый диагноз не показывается, а заменяется на «неопределённо»
6. доля повреждённой площади листа (по цвету) → тяжесть LOW / MODERATE / HIGH
7. возможные причины: по цветам листа + по показаниям датчиков (источник помечен: image / sensor)
8. рекомендации, сводка, сравнение с прошлым осмотром этой же точки (лучше / хуже / так же)
   ▼
JSON + страница результата + история (SQLite) + панель /dashboard с графиком по каждой точке
```

Что считает каждый этап и из каких файлов он состоит — в `maxik_cv/tomato/` (один модуль — одна ступень);
`service.py` — единственная точка входа, которой пользуются и API, и веб-страница.

### Как запустить

```bash
python webapp.py                                   # http://127.0.0.1:5055/tomato  и  /dashboard
MAXIK_HOST=0.0.0.0 MAXIK_API_TOKEN=... python webapp.py     # чтобы робот в той же сети мог достучаться
```

На роботе (Raspberry Pi), `scripts/send_to_server.py`:

```bash
python3 scripts/send_to_server.py --url http://СЕРВЕР:5055 --token ... --point ряд1-куст3 --soil 0.4 --temp 24 --humidity 0.6
python3 scripts/send_to_server.py --local --point ряд1-куст3        # без сети, анализ на роботе (нужны models_*/*.onnx)
python3 scripts/send_to_server.py --url ... --fallback-local        # сервер, а если недоступен — сам, фото уйдёт позже
python3 scripts/send_to_server.py --url ... --resend                # досылка накопившихся в outbox/
```

Переменные окружения сервера: `MAXIK_API_TOKEN` (токен для `/api/*`), `MAXIK_UI_PASSWORD` (пароль на веб-страницы,
`/api/health` остаётся открытым), `MAXIK_HOST`, `MAXIK_DB_PATH` (файл истории). Облако: `Dockerfile` +
`requirements-server.txt`; без постоянного диска история пропадает при переразвёртывании.

`POST /api/tomato?point=ID&soil_moisture=0..1&temperature=°C&humidity=0..1` — тело: JPEG (или форма `photo`).
Ответ — JSON: `condition`, `conditionConfidence`, `severity`, `affectedFraction`, `candidates` (топ-3 версии модели),
`possibleCauses`, `recommendations`, `warnings`, `trend`, `summary`, `imageQuality`.
Кадры, отклонённые как плохие или «не растение», в историю не пишутся — они ничего не говорят о состоянии растения.

### Что измерено (и чего нет)

Все числа — на отложенных данных PlantVillage (лабораторные снимки листа на однотонном фоне), кроме строк «деградация».
Скрипты: `scripts/evaluate_tomato_pipeline.py`, `python -m unittest discover -s tests`.

| Что | Результат | Как получено |
|---|---|---|
| Классификатор болезней, 10 классов | 99,9 % (1539 из 1540) | отложенная выборка; почти одинаковые снимки одного листа удалены из разделения (`dedup_split.py`) |
| Весь конвейер целиком | верно 394 из 396, 1 «неопределённо», 1 отказ, **0 уверенных ошибок**; 54 мс на кадр (CPU ПК) | `evaluate_tomato_pipeline.py --per-class 40` |
| Размытый кадр (гаусс σ=1,5 / смазка 9 px) | верно 167 и 153 из 200 (84 % и 77 %), остальные отклонены, **0 уверенных ошибок** | те же фото, искусственная деградация; для сравнения прежняя модель без аугментации размытием была уверенно неправа на 18 и 42 из 200 |
| Сильная смазка (σ=3 / 21 px) | отклонено 130 и 152 из 200 (65 % и 76 %); все прошедшие фильтр кадры (70 и 48) классифицированы верно, 0 уверенных ошибок | то же |
| Ворота «растение?» | тест 99,9 %; распознаны 60 из 60 в каждом из 7 видов растений (томат, яблоня, кукуруза, клубника, цветы…); 0 из 99 настоящих не-растений и 0 из 300 синтетических шумов/полос/шахматок приняты за растение | `train_plant_gate.py`; синтетика того же рода, что в обучающих негативах |
| Доля повреждения у здорового листа | медиана 2 %, 90-й перцентиль 6 % | `maxik_cv/tomato/lesion.py` |

Подборы по данным, которые стоит знать: порог резкости (метрика по обоим направлениям в масштабе 256 px; обычная
дисперсия Лапласа браковала чёткие гладкие листья и пропускала смазку в одном направлении; цена нового порога:
8 из 1540 нормальных тестовых снимков (0,5 %) отклоняются как «смазанные», хотя модель на них права, а ещё 11,6 %
проходят с предупреждением «кадр мягкий» — для робота, который может переснять кадр, это приемлемо), порог яркости
(по перцентилям, иначе лист на чёрном фоне считался «тёмным»), порог «стабильно» в тренде (10 пунктов, т. к. у здоровых
листьев разброс до 6).

**Не проверено / ограничения — обязательно в отчёт:**

1. **Ни одной реальной фотографии с камеры робота.** 99,9 % говорят о том, что PlantVillage лёгкий набор, а не о
   точности в поле: известно, что модели, обученные только на нём, на полевых снимках работают заметно хуже
   (другие фон, свет, угол, несколько листьев). Нужна проверка на независимых снимках (см. `DATA_COLLECTION_GUIDE.md`;
   `evaluate_tomato_pipeline.py --labelmap plantdoc` готов для открытого набора PlantDoc).
2. **«Насколько плохо» — оценка по цвету, а не измерение.** Хорошо видит крупные пятна (ранняя/поздняя фитофтороз,
   септориоз), почти не видит мозаику, клеща, закручивание, мелкую пятнистость — у них тяжесть будет LOW, даже когда
   болезнь серьёзная (в ответе в этом случае есть предупреждение). Границы 10 % / 30 % взяты из ТЗ, экспертной
   разметкой тяжести не калибровались.
3. **Вид растения** — заглушка: фото огурца с хорошими листьями будет оценено как томат.
4. Ворота «растение/не растение» проверены на фото из Imagenette, на размытых и однотонных фонах и на синтетическом
   шуме/полосах (до дообучения на синтетических негативах шум пикселей принимался за растение в 60 из 60 случаев);
   **на реальных текстурах (почва, горшок, стена, пол) не проверены** — это следующее слепое пятно.
5. Скорость измерена на ПК, **на Raspberry Pi 4 не запускалось**; съёмка `picamera2` проверена только по коду.
6. Причины («возможные причины») — эвристики по цвету и порогам датчиков из общих агрономических источников, не
   диагноз; пороги датчиков — стартовые, нужна калибровка под ваши датчики.

## Архитектура

```
фото с Pi Camera 3 (фиксированные экспозиция и баланс белого)
        │
        ▼
1. Сегментация растения (ExG + HSV)  ──►  2. Цветовые индикаторы: доля зелёного/жёлтого/коричневого,
        │                                     насыщенность, площадь растения в кадре
        ▼                                            │
3. Кроп растения → CNN (MobileNetV3, ONNX)           │   + датчики (влажность почвы и т.д.)
        │                                            │   + прошлый осмотр этой же точки (история)
        ▼                                            ▼
4. Слияние: 0.75·CNN + 0.25·правила → класс + уверенность
        │
        ▼
5. уверенность < порога → "unknown / нужна проверка человеком"
   отчёт JSON: класс, причины («жёлтая площадь 23%», «влажность почвы низкая»), рекомендация
```

Почему так:
- **Правила работают сразу, без датасета**, и объяснимы (понятно пользователю и комиссии).
- **CNN** ловит то, что правилами не описать (пятна, текстура, поникшие листья).
- **История по точке** — главное преимущество робота перед приложением-фотоопределителем: он видит
  *изменения* (растение «сжалось» на 20% → увядание/слабый рост).
- **Класс unknown** через калиброванный порог уверенности — честная граница ИИ (риск из раздела 22).

## Структура

| Файл | Что делает |
|---|---|
| `maxik_cv/segment.py` | маска растения, цветовая статистика, кроп, отладочная визуализация |
| `maxik_cv/rules.py` | правила и пороги (калибруются на своих фото) |
| `maxik_cv/classifier.py` | инференс ONNX (работает на Pi без PyTorch) |
| `maxik_cv/pipeline.py` | полный конвейер → отчёт |
| `maxik_cv/history.py` | SQLite-история осмотров по точкам |
| `scripts/capture_pi.py` | съёмка на Pi с блокировкой AWB/экспозиции, сохранение в датасет или осмотр |
| `scripts/prepare_dataset.py` | деление train/val/test **по растениям** (без утечки) |
| `scripts/train.py` | дообучение MobileNetV3/EfficientNet на GPU, калибровка, экспорт ONNX |
| `scripts/evaluate.py` | точность, матрица ошибок, precision/recall, подбор порога unknown, лог ошибок |
| `scripts/inspect_image.py` | прогон на фото/папке с отчётом и маской |
| `scripts/make_synthetic.py` | синтетические картинки только для проверки кода |

## Порядок работы

```bash
# 1. ПК: окружение (уже создано в .venv)
.venv/Scripts/activate

# 2. Сбор данных на Pi: data/raw/<класс>/<idрастения>_<точка>_<время>.jpg
python3 scripts/capture_pi.py --point p1 --label healthy --plant basil03

# 3. Деление и обучение (ПК, GTX 1660 Ti)
python scripts/prepare_dataset.py --src data/raw --dst data/split
python scripts/train.py --data data/split --epochs 30

# 4. Оценка для отчёта TRL 4
python scripts/evaluate.py --data data/split/test --model models/plant_health.onnx
python scripts/evaluate.py --data data/split/test --rules      # baseline без нейросети

# 5. Pi: скопировать maxik_cv/, scripts/, models/plant_health.onnx + .json
python3 scripts/capture_pi.py --point p1 --inspect
```

## Что уже проверено (синтетические данные, только проверка кода)

- Окружение: `.venv`, PyTorch 2.14 + CUDA на GTX 1660 Ti, OpenCV 5, ONNX Runtime.
- Весь цикл работает: генерация → деление → обучение на GPU (≈1–2 с на эпоху) → калибровка → ONNX (один файл, ~17 МБ) → оценка.
- История точки: растение, уменьшившееся на 87%, → `weak_damage` (94%), без истории — не видно.
- Цифры точности на синтетике **ничего не значат** для реальных растений: в отчёт идут только фото с Pi.
- Найденные и исправленные ловушки: почва попадает в «коричневый» HSV-диапазон (сухой лист считается только
  если отличается от цвета почвы в Lab); CNN должна видеть кадр так же, как при обучении (без кропа);
  калибровка температуры — перебором, а не LBFGS.

## План по данным (самое важное)

1. **Свои фото — основа.** 4 класса × 60–100 фото, 10+ растений на класс, одна и та же камера и свет.
   Состояния вызывать контролируемо: не поливать часть растений (dryness), перелив/нехватка света/азота
   (yellowing), механическое повреждение/обрезка (weak_damage). Снимать серию каждый день — это и датасет, и история.
2. **Публичные датасеты — для предобучения** (PlantDoc, PlantVillage, Plant Pathology), затем дообучение
   на своих через `--init`. Модель, обученная только на PlantVillage, на реальных фото работает плохо —
   фон и свет другие.
3. **Не делить фото одного растения между train и test**, иначе 95% превратятся в 60% на новом растении.
4. В аугментациях **нет сдвига оттенка (hue)**: цвет листа и есть признак.
